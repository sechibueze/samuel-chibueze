Engineering philosophy

I build software people can bet their livelihoods on. These principles shape every system I design.

01

Architect before you build

Before code, I define boundaries, data flow, failure modes and cost at scale, and I write down the trade-offs. Good system design is what lets a small team ship fast without painting itself into a corner.

02

Reliability is a feature, not a phase

When software moves money and books someone’s working day, failure is lost income. I design for idempotency, verified webhooks, locked transactions and monitoring from the first commit.

03

Start with the person, not the stack

The best solution is the one people will actually use, whether that is a WhatsApp message instead of an app install or a booking flow for a salon owner who used to run on a notebook.

04

Own the problem end to end

As a three-time founding engineer, I stay hands-on from API design to deployment, so every architectural decision is tested against real constraints, not slideware.

05

If it matters, measure it

My petroleum engineering training taught me to reason from data. I set a baseline, make the change, and prove it with numbers like latency, success rate and uptime.

06

Design for change, scale on demand

I ship the MVP first, but behind clean boundaries (service layers, provider-agnostic integrations, events and caching) so growth to a million users is an upgrade, not a rewrite.

07

Make AI earn its place

I treat AI as an engineered system: grounded answers, rate limits, caching, observability and cost control, so it delivers value without surprise bills or surprise behaviour.
